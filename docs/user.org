#+title: misskey.el user guide
#+options: toc:2 num:nil

* Authorize

Select one HTTPS instance origin and a local credential label:

#+begin_src emacs-lisp
(setq misskey-instance-url "https://example.social"
      misskey-auth-source-user "alice")
#+end_src

The origin cannot contain credentials, a path, a query, or a
fragment.  Account identity uses the origin plus the stable remote
user ID returned by Misskey.

~M-x misskey-authorize~ opens a fresh MiAuth consent session and
atomically replaces the configured credential.  First use of the home
timeline or composer also authorizes when no credential exists.  The
bearer token and remote user ID are saved together through the first
configured encrypted netrc/authinfo source ending in ~.gpg~.
Authorization refuses to write a plain source.

Token-only records from older versions are rejected.  Run
~M-x misskey-authorize~ rather than editing the stored record by
hand.  Existing credentials do not gain new scopes automatically.

Requested scopes: ~read:account~, ~read:notifications~,
~write:notes~, ~write:reactions~, ~write:favorites~,
~write:following~, ~write:notifications~, and ~write:drive~.

An instance on a non-default HTTPS port uses ~misskey-PORT~, such as
~misskey-8443~, as the auth-source service label.

* Note views

Timelines, threads, profiles, and note searches enable native ~visual-line-mode~
by default.  Long text and links wrap at the window edge while retaining the
renderer’s avatar and reply indentation.

| Key | Action |
|-----+--------|
| ~g~ | refresh |
| ~n~ / ~p~ | next or previous note |
| ~N~ | older page, keep semantic position |
| ~RET~ / mouse-2 | activate a text link; otherwise reveal or hide a content-warning body |
| ~t~ | open the thread at point |
| ~r~ / ~q~ | compose a reply or quote |
| ~a~ | prefix contextual note and user actions |
| ~O~ | open a Note or profile URL from the current view |
| ~B~ | open the link at point, or the current Note, in a browser |
| ~w~ | copy that link or Note URL |
| ~?~ | contextual Transient menu |

Timeline ~TAB~ cycles Home, Local, Social, and Global in one view
while retaining each mode's loaded notes and position.  Settled pages remain
cached for the account when the timeline closes; reopening refreshes the
selected mode without reviving its old request.  Profile ~TAB~
cycles Notes, Notes + replies, and Media; ~f~ and ~F~ open followers
and following directories.  Each ~misskey-search~ invocation owns an
independent result set, cursor, request, and content-warning state.

HTTP(S) links, mentions, and hashtags in ordinary and quoted Note text are
actionable without changing copied text.  Code and ~<plain>~ content remain
literal, and hidden CW bodies do not expose links.  A bare mention in a
remote author's text resolves on that author's server; hashtags use
~notes/search-by-tag~, not free-text search.

Own-instance Note and profile URLs open existing client views.  Recognized
remote object URLs resolve through the current account's instance; credentials
are never sent to the linked host.  Other web links open in the browser.
Resolution stops when its view closes or another navigation supersedes it.
The URL prompt is also available as ~M-x misskey-navigation-open-note-url~;
browser and copy commands are ~misskey-navigation-browse~ and
~misskey-navigation-copy-link~.  The bindings above are the ordinary
major-mode bindings; Evil's client-local bindings are listed below.

** Actions

Press ~a~ followed by:

| Key | Action |
|-----+--------|
| ~r~ / ~R~ | add a reaction string or remove the current reaction |
| ~f~ / ~F~ | favorite or unfavorite the note |
| ~n~ | create a pure renote |
| ~d~ | confirm and delete the note row at point |
| ~+~ / ~-~ | follow or unfollow the user at point |

Successful actions install account-scoped overrides and invalidate
matching note or user resources in every live Appkit view.

* Media

Graphical note views fetch author avatars plus MIME-qualified image
and video thumbnails asynchronously.  Every Drive attachment remains
visible and actionable.  Audio, PDF, archives, and other generic
files open their original HTTPS resource.  Text renders first.
Sensitive media stays hidden until the user reveals its note.
Preview work is queued per account with bounded concurrency; large pages
continue loading as earlier downloads finish.

Media caches are isolated by server and account.  Opening an attachment
belongs to the note surface where it was activated: closing that surface
or opening another attachment cancels the pending open.  Download failures
appear in the surface header, without opening an unrelated viewer.

#+begin_src emacs-lisp
(setq misskey-timeline-show-avatars nil
      misskey-timeline-show-media nil)
#+end_src

~misskey-timeline-media-preview-width~ and
~misskey-timeline-media-preview-height~ bound inline previews.

* Compose

The Appkit compose surface keeps generated context and status outside
the editable body.

| Key | Action |
|-----+--------|
| ~C-c C-c~ | publish the draft once |
| ~C-c C-v~ | Public, Home, Followers, or Specified visibility |
| ~C-c C-a~ | attach a readable local file |
| ~C-c C-d~ | detach one file from the current note |
| ~C-c C-w~ | edit the content warning; empty input clears it |
| ~C-c C-l~ | toggle local-only publication |
| ~C-c C-r~ | add a recipient by ~@user[@host]~ or stable user ID |
| ~C-c C-x~ | remove a recipient |
| ~C-c C-m~ | reload the instance text limit |
| ~C-c C-o~ | Transient draft options |
| ~C-c C-n~ | insert another note after the current part |
| ~C-c C-p~ | remove the current extra note |
| ~C-c C-k~ | abandon an idle draft |

Each note accepts up to 16 files.  File-only notes are supported.
Local files stream to ~drive/files/create~; the compose State field
shows a progress bar and percent for the file currently uploading.
A multi-note draft publishes in order and makes each later note a
reply to the preceding created note.

The header shows each part's Unicode code-point count and the instance's
~maxNoteTextLength~.  All parts and attachments are validated before any
upload or publication starts.  Missing or failed limit discovery blocks
publication rather than guessing a limit; ~C-c C-m~ retries without changing
the draft.

Replies inherit the original visibility, CW, and local-only restriction.
Visibility cannot be widened beyond the target, and a required local-only
restriction cannot be disabled.  Specified replies retain the original
recipients and author, excluding the sender.  Specified publication requires
resolved recipient IDs; it is audience-limited posting, not encrypted chat.
Specified Notes, another author's followers-only Notes, and channel Notes
cannot be quoted through this composer.

Visibility, CW, local-only, and recipients apply to every part and are
captured with the publication operation.  Later metadata or recipient
lookups cannot alter a stopped draft or overwrite a newer recipient choice.

After a successful upload, its Drive ID stays on that compose item.
A later publish failure leaves the draft editable; a deliberate retry
reuses that Drive file.

Stopping the account or compose Surface cancels its local publication work
and preserves an editable draft.  Late responses cannot resume its reply
chain.  A dispatched write may still have reached the server: inspect the
server before copying the retained content into a new draft and retrying.

* Notifications

Opening, refreshing, and paging notifications always send
~markAsRead: false~.  ~M~ is the only command that marks all
notifications read.  ~RET~ opens the notification's note or actor
when one is present.

* Menus and Evil

~?~ or ~M-x misskey-menu~ opens the browsing Transient.  Global view-opening
commands work outside a Misskey view; Note, link, and user actions require
the appropriate live context.  Commands act in the originating buffer,
not in the popup.  Notification ~M~ remains an explicit mark-all action.

~C-c C-o~ or ~M-x misskey-compose-menu~ opens draft options.  Visibility,
CW, local-only, recipients, files, and parts operate on the existing draft;
labels and availability update after each edit.  The menu stays open for
option changes.  Only its explicit ~C-c C-c~ suffix publishes.

When Evil is available, Appkit's optional integration provides normal and
motion bindings in browsing views:

| Key | Action |
|-----+--------|
| ~?~ | contextual menu |
| ~g r~ | refresh |
| ~g j~ / ~g k~ | next or previous entry |
| ~g n~ | older page |
| ~RET~ | link/CW, or directory/notification activation |
| ~TAB~ | existing timeline/profile or directory cycle |
| ~r~ / ~Q~ | reply or quote in Note views |
| ~c~ | compose |
| ~g o~ / ~g O~ | browser / open a supplied URL in Note views |
| ~g y~ | copy the link or Note URL |
| ~a~ | existing contextual action prefix |
| ~M~ | explicitly mark notifications read, in the notification view |
| ~q~ | close the window without discarding its buffer |

Normal search and word motions, including ~n~, ~w~, and ~B~, are not
replaced.  Compose starts in insert state; normal-state ~i~ returns to the
editable input.  Its ~C-c~ controls remain available.

Integration is local to Misskey maps, works with either Evil load order,
and honors ~appkit-evil-enable-integration~.  Set that option to nil before
loading Misskey to opt out.  ~M-x misskey-evil-setup~ reapplies integration
after changing local maps.

* Write safety

Every authenticated JSON request and Drive upload uses one bounded
streaming curl dispatch.  Redirects and retries are disabled.  The
bearer token stays out of request bodies and process arguments.
Appkit owns each request and cancels remaining work when the account
session stops.

After dispatch, any failure is an unknown remote outcome.
~misskey.el~ never retries a Misskey write automatically.  The
affected compose draft remains available so the user can inspect the
server before trying again.
